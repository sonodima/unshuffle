# Translations (i18n)

UNSHUFFLE ships in 10 languages: Italiano (source), English, Español, Français,
Deutsch, Português (Brasil), Русский, 日本語, 한국어, 简体中文. Left-to-right scripts
only. No dependency: `src/i18n/` is a small typed layer over `Intl`.

## How it works

- **Catalogs**: `src/i18n/locales/<locale>/<namespace>.ts`, aggregated by
  `locales/<locale>/index.ts`. Italian (`it`) is the source of truth and is always
  bundled; every other locale mirrors its shape exactly (`satisfies Catalog`) and
  is loaded on demand as its own chunk (`LOADERS` in `src/i18n/index.ts`).
- **Namespaces** follow the code: `home`, `lobby`, `round` (preparing / intro /
  play), `reveal`, `final`, `shell` (app shell, connection dialogs, toasts,
  reactions), `ui` (design-system defaults), `board` (snippet board), `game`
  (messages produced by the host / store / network / Deezer, difficulty names),
  `names` (random nickname parts).
- **Keys** are typed: `t('lobby.start')` with a key that doesn't exist does not
  compile. Keys are camelCase, grouped by component or section
  (`lobby.picker.searchPlaceholder`, `round.hud.rank`). Two keys may hold the same
  Italian text only when they sit in different places with different constraints
  (a 10-character tab vs a section title); a comment above each says where.
- **Language choice**: saved choice (`localStorage['unshuffle:locale']`) → the
  browser's languages → English. `initI18n()` runs before the app module is
  imported (`src/main.tsx`), so the first render and the random nickname are
  already in the right language. `setLocale()` switches at runtime and remembers
  the choice (the last of several quick calls wins); the globe button
  (`LanguagePicker` in `components/ui`) sits in the Home and Lobby headers.

## API

```ts
import { t, tm, tl, td, formatNumber, formatList, formatOrdinal } from '../../i18n'   // non-React code, at call time
import { useT, useLocale, rich } from '../../i18n/react'                            // components

const t = useT()                         // re-renders the component on a language change
t('lobby.start')                         // "Inizia partita"
t('ui.timer.secondsLeft', { count: 3 })  // plural chosen by `count` with Intl.PluralRules: "3 secondi rimasti"
t('game.host.notEnoughTracks', { count: 5000 })   // numbers in params are formatted: "5.000" / "5,000"
rich(t('home.hero.tagline'), { b: (c) => <strong>{c}</strong> })   // "<b>…</b>" in the message
tm(msg)                                  // a Msg from the host / store / network
tl('names.nouns')                        // a list of strings
td('lobby.chips')                        // per-language data (objects / numbers)

formatNumber(4428)                       // "4.428" / "4,428": thousands are ALWAYS grouped (plain it-IT
                                         // and es-ES would print "4428"); options go to Intl.NumberFormat
formatList(['Giulia', 'Tommy', 'Marco']) // "Giulia, Tommy e Marco" / "Giulia, Tommy, and Marco"
t('round.hud.rank', { rank: formatOrdinal(2) })   // "2º posto" / "2nd place" (see Ordinals)
```

Formatters are cached per language and options, so animations may call them
every frame. `registerCatalog(locale, catalog)` installs a catalog without a
loader: it exists for tests and tooling only (fake catalogs in
`tests/unit/i18n.test.ts`); the app registers languages in `LOADERS`.

Messages:

- Plain strings with `{param}` placeholders.
- Plurals are objects keyed by `Intl.PluralRules` categories. Italian and English
  use `one`/`other`; Russian `one`/`few`/`many`/`other`; Japanese, Korean and
  Chinese only `other`. Never name a key `other` outside a plural. A category the
  game never reaches may be left out (`other` stands in): the `many` of Italian,
  Spanish, French and Portuguese only applies to exact millions. Mind that French
  and Brazilian Portuguese `one` also covers 0 ("0 point").
- Inline markup: `<b>…</b>`, `<em>…</em>` etc., rendered with `rich()`; not nested.
  Every form of a plural uses the same tags. A tag may be empty when the code puts
  an element there (`<play></play>` → the ▶ icon), and may appear twice when the
  word order needs it (`<word>第</word><n>1</n><word>回合</word>`).
- Comments (`/** … */`) above a key tell translators where it shows, how much room
  it has, what each `{param}` holds and whether CSS uppercases it. Read them.

### Ordinals

A place or a position is written by `formatOrdinal(n)`, never by a `º` typed into
a message. Its pattern is `ui.ordinal` (a plural object, `{n}` = the number),
picked with the language's **ordinal** plural rules: Italian `{ other: '{n}º' }`,
English `{ one: '{n}st', two: '{n}nd', few: '{n}rd', other: '{n}th' }`, German
`{ other: '{n}.' }`. Messages then take the ready-made ordinal as a string param
and add only the words around it (`'{rank} posto'`, `'era {pos}'`). Keep
`ui.ordinal` neutral in gender and case (it serves rankings and positions in a
sequence); a language that needs a counter word (位, 번째) puts it in the messages.

### Messages from the game

Only the UI produces text. The host, store, network and Deezer layers pass `Msg`
values; `NetError` / `DeezerError` carry a key as their message. The UI decides
by **key** (`msgKey(msg) === 'game.net.roomNotFound'`), never by comparing text.
Toast tone also comes from the key (`components/shell/toastCopy.ts`): `game.*`
keys and keys ending in `Failed` / `Error` are warnings, any other key a success
(`lobby.invite.linkCopied` ✓, `lobby.invite.copyFailed` ⚠). Name new notices to fit.

## Rules

1. **Every user-visible string goes through the catalog**: visible text, `aria-label`,
   `title`, `alt`, `placeholder`, tooltips, toasts, dialogs, `document.title`,
   screen-reader announcements (dnd-kit), keyboard key names (`Spazio` → `Space`),
   units and short labels (`s`, `pt`), fallbacks.
2. **Never build sentences from fragments** (`a + ' ' + b`, `${n} ${word}`): give the
   whole sentence to the catalog with params, so each language can reorder it.
3. **Non-UI code never produces text.** The host, store, network and Deezer layers
   pass `Msg` values (a key, or `{ key, params }`) and throw `AppError(msg)`; the
   UI shows them with `tm()`, in the viewer's language. Messages broadcast by the
   host (preparation steps, info events) are keys, so every peer reads them in its
   own language.
4. **Call `t()` at render / call time**, never at module top level (that would freeze
   the language). Memoized values that contain text depend on `useLocale()`.
5. **Uppercase is CSS** (`text-transform`), never typed into the catalog. Leave room:
   German and Russian run ~30% longer than Italian; buttons and pills must wrap or
   shrink gracefully instead of clipping.
6. **Not translated**: the UNSHUFFLE brand, room codes, emoji, player names, song /
   artist / album / playlist names from Deezer, "BPM".
7. **Numbers** go through `formatNumber()` (or as params); timers use the digits
   format of `formatClock`.

## Guards

```sh
bun test ./tests/unit/i18n-hardcoded.test.ts   # fails on user-facing text outside the catalog
bun tests/support/i18n-scan.ts                 # the same scan as a report grouped by file (exit code 1 on findings)
bun test ./tests/unit/i18n-catalog.test.ts     # the catalog is plain data; every registered language mirrors it
                                               # (params, tags, plural categories, lists / data); every key follows
                                               # the current language
bun tests/support/i18n-check.ts <code> [--strict]   # the same per-language checks as a report; --strict also lists
                                               # messages left identical to Italian
bun test ./tests/unit/i18n.test.ts             # the core: lookup, plurals, formatting, detection, switching
```

The scanner (`tests/support/i18n-scan.ts`) parses every production `.ts` / `.tsx`
under `src/` (catalogs excluded) with the TypeScript compiler API and reports text
in JSX, in text attributes and props (`aria-*`, `title`, `alt`, `placeholder`,
`label`, any `*Label` / `*Title` / `*Text`…), in `{ label: … }`-style object
properties, in toast / dialog calls, in `document.title` / `textContent` /
`setAttribute('aria-label')` and dnd-kit announcements, plus any other string that
reads as Italian prose (logs and errors must be English). Allowed: strings without
letters, catalog keys, UNSHUFFLE / BPM, a single capital (key caps), CSS class
lists, arguments of `t()`. A deliberate exception takes a comment with a reason, on
the same line or alone on the line above:

```tsx
<span>UN</span> {/* i18n-ignore: brand mark on the record label */}
```

A comment without a reason is reported too.

## Adding a language

Copy `locales/en/` to `locales/<code>/`, translate every file (the type checker
lists what's missing), add the code to `LOCALES` / `LOCALE_INFO`
(`src/i18n/locales.ts`) and a loader to `LOADERS` (`src/i18n/index.ts`): one
lazy chunk per language. Check it with `bun tests/support/i18n-check.ts <code>`
(CI runs the same checks on every registered language) and with the bounds suite:
`node tests/e2e/i18n-bounds.mjs <baseUrl> <code>`.
